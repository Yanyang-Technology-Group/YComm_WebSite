# WebSocket 通知与 API 文档实现计划

目标：保留 Next.js + Hono REST 契约，增加 Cookie 认证的 `/api/ws` 刷新提示。

架构：自定义 Node HTTP server 在 3000 转交普通请求给 Next，只在 Upgrade 分派 WebSocket。通知发布接口放在 notify，进程级共享总线跨 Next 打包边界；实时模块只维护用户连接与会话状态。数据库仍是数据真相来源。

- [x] 在 apps/api/src/realtime/server.test.ts 使用真实 PGlite 与 ws 客户端先验证失败：Cookie、过期/撤销/用户状态、Origin/HTTPS、隔离、多连接、断开、心跳和会话复查。
- [x] 实现 packages/notify/src/events.ts 类型与发布接口，createNotification 成功插入后发布；实现 apps/api/src/realtime/server.ts，按用户投递，不传实体/凭据。
- [x] apps/web/server.ts 共用端口，保留 Next catch-all；更新 package scripts、Docker/Compose 和部署文档。验证 Next 打包后的通知能到达实际 WSS 连接。
- [x] 独立文档任务逐条阅读所有 routes 与领域模型，编写 docs/API.md；按用户后续要求不保留 Flutter 示例。
- [x] 运行 lint、typecheck、test、production build，独立代码审查并修复实际发现。

安全选择：Origin 必填；Flutter 原生显式发送 SITE_URL origin。生产必须配置 HTTPS SITE_URL；仅在 TRUST_PROXY_HEADERS 开启且端口受可信代理隔离时接受 X-Forwarded-Proto=https。连接周期复查会话，拒绝任何 query，限制连接数量与缓冲区，关闭时解除监听并清理计时器。

扩展：单实例、无事件持久化；多实例替换通知总线为 Redis Pub/Sub 或 PostgreSQL LISTEN/NOTIFY。重连必用 REST 补拉。
